# SSH 中转主机

1. 先保存并配置好中转主机的地址、端口和登录凭证。
2. 新建或编辑目标连接，在“中转主机（可选）”中选择该主机。
3. 填写目标服务器的地址和登录凭证，点击“测试连接”或保存后连接。

目标地址由中转主机连接，可以使用中转主机能够访问的内网 IP 或域名。
中转主机和目标服务器分别使用各自的密码、私钥或免密码认证配置，首次连接时分别确认主机指纹。中转主机需要允许 SSH TCP 转发。

终端、SFTP、AI 命令和端口转发复用目标服务器的 SSH 连接，但不共享交互式 Shell。人工终端中的 `sudo -i`、`cd` 和环境变量不会被 AI 继承。断开连接时会释放整条中转链路，重新连接时重新加载中转配置和凭证。

中转主机也可以选择自己的中转主机，实现多级连接。循环引用、已删除的中转主机和缺少凭证会阻止连接并显示错误。选回“直接连接”即可取消中转。

## AI 的 root 授权

需要 root 时，AI 通过 `request_root` 请求授权。无论当前是否为自动审批模式，都需要在客户端确认；在密码框输入 sudo 密码后点击“授权本轮 root”，已配置免密 sudo 时可留空。认证失败可以在同一请求中重试。点击“取消”只拒绝这一次授权申请，AI 会收到“用户拒绝，未执行”的工具结果并继续对话，不会停止整轮任务；如果正在认证，会中止这一次认证，迟到结果不会生效。密码仅用于当前认证，不保存，也不进入 AI 对话、历史或窗口状态快照；独立窗口仅通过一次性授权动作将密码交给主引擎。

授权成功后显示“root · 仅本轮”，本轮 AI 的 SSH 命令通过独立的 root 通道执行，不改变人工终端、SFTP 或 MCP 工具的权限。每条命令使用独立子 Shell，标准输入为 EOF，`cd` 和 `export` 不跨命令保留。任务结束、异常、停止任务或断线会关闭提权通道；“结束提权并停止”会同时停止本轮任务，不会自动继续以普通用户执行。停止只请求终止远程进程，已完成的操作不会回滚，必要时应检查服务器状态。

此流程使用非交互 `sudo -S -i`，要求服务器允许启动 root 的 POSIX Shell。强制 TTY（`requiretty`）、MFA 或其他交互式 PAM 验证不受支持；只允许个别 sudo 命令的白名单也不足以授权 root Shell。无需为此放开 sudoers：不满足服务器策略时，由用户在人工终端执行需要提权的操作。
